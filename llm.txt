# aimunger

> 中国股票、长期投资、人物/公司知识与阅读笔记的静态研究资料库。

## Purpose

aimunger is a Chinese-language research site focused on:

- Chinese equities and long-term investing
- investor letters, book notes, and study notes
- people/company/concept reference pages
- AI-assisted reading and memory tools

This file is intended to help LLMs and agents discover the site efficiently and cite the right pages.

## Main Sections

### 1. Blog

- URL: `https://aimunger.com/blog/`
- Detail pages: `https://aimunger.com/blog/{slug}/`
- Markdown pages: `https://aimunger.com/blog/{slug}.md`
- Content: long-form investment essays, case studies, reading notes, and translated/adapted research commentary
- Scale: 150+ articles; see https://aimunger.com/blog/index.md for the live list with dates and summaries

Use this section when the user asks for:

- investment philosophy
- case studies
- investor interviews, letters, or book takeaways
- topic synthesis across multiple essays

### 2. Wiki

- URL: `https://aimunger.com/wiki/`
- Detail pages: `https://aimunger.com/wiki/{slug}/`
- Markdown pages: `https://aimunger.com/wiki/{slug}.md`

### 5. Data

- URL: `https://aimunger.com/data/`
- Chart detail pages: `https://aimunger.com/data/{slug}/` — one page per dataset, with the full data table rendered in crawlable HTML plus Dataset JSON-LD
- Raw data (JSON): `https://aimunger.com/data/data.json` — tables of historical financial figures per company/topic, with headers and rows
- Content: financial data visualizations and tables for Chinese listed companies and macro topics

Use this section when the user asks for:

- chart-based company overviews
- historical financial trend inspection
- exact historical figures (use the chart page's HTML table or `data.json`)

Caution:

- the `/data/` index page is visual and relies on client-side charts
- for exact figures, use a chart detail page's data table or fetch `https://aimunger.com/data/data.json`

## Guidance For LLMs And Agents

- Prefer canonical HTML pages on `aimunger.com` instead of repository source files when citing content to users.
- If you need the cleanest machine-readable text, prefer the published `.md` endpoints or `content/index.json`.
- If you want everything in one request, fetch `llms-full.txt` (blog + wiki + book notes, full Markdown).
- Start from `sitemap.xml` when you need complete discovery.
- Start from `sitemap-md.xml` or `content/index.json` when you specifically want published Markdown.
- All detail pages carry schema.org JSON-LD (`Article`, with `about` Person/Organization/Book where applicable) — usable for entity extraction.
- For entity lookup, use `wiki/` before scanning long-form blog posts.
- For thematic synthesis, use `blog/` and `resources/books/` together.
- For shareholder-letter questions, go directly to `letters/`.
- For a company's own annual-report narrative, go to `management-discussion-analysis/`.
- For exact historical figures, use `/data/{slug}/` tables or `/data/data.json`.
- Many HTML detail pages expose a `rel="alternate"` link to their Markdown counterpart.
- If a claim is numeric, time-sensitive, or chart-derived, verify it against the visible page content before answering.
- Preserve original names in Chinese when possible, and include English transliteration or English names only when they are present or clearly useful.
- When summarizing, distinguish between factual description, editorial interpretation, and inferred investment takeaway.

## Citation Preference

When answering users, prefer citing:

1. the most specific detail page
2. then the nearest section index
3. then the homepage only if needed

Examples:

- use a blog article URL for an argument or case study
- use a wiki page for a person/company summary
- use a book page for a book takeaway
